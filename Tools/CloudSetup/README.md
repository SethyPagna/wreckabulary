# Cloud tools and checks

Use the existing checkout; a cloud task is already isolated. Download Git LFS
objects before opening Unity (`git lfs pull`, then `git lfs fsck`).
Reviewed web GLBs, generated UI images and art-review renders are stored directly
in Git; each is below 8 MB. The original supplied art retains its existing LFS
storage. This avoids a separate LFS upload prerequisite for the new derivatives.

The rules harness requires .NET9. The rootless Linux installer is pinned to
SDK9.0.318; its hashes were checked against Microsoft's signed repository metadata.
It preserves TLS and checksum checks:

```sh
python3 Tools/CloudSetup/install-dotnet.py
export DOTNET_ROOT=/workspace/.cloud-setup/dotnet-root/usr/share/dotnet
export PATH="$DOTNET_ROOT:$PATH"
dotnet run --project Tools/RulesHarness
```

An optional C# source check compiles all six assemblies separately against installed
Unity DLLs, using .NET's compiler: `python3 Tools/CloudSetup/compile-sources.py`.
It records the exact package DLL paths. Without a successful project import it uses
editor template-cache DLLs, which may differ from the pinned package versions.
This does not execute Unity or validate its import, physics, rendering or builds.

`python3 Tools/CloudSetup/verify-home-storage.py` runs the actual home storage and
history tests against temporary files. Its small .NET host supplies canonical
JSON configuration and an Application-path shim that throws if used; every test
injects its own directory. This verifies file replacement, rejected-save recovery,
per-map isolation and snapshot history, while Unity initialization/UI stay unrun.

Unity is pinned by `ProjectSettings/ProjectVersion.txt` to 6000.6.3f1. Use the
official editor and matching platform modules. Unity Personal must be activated
through Unity Hub on the machine where the editor runs. Do not put credentials
or a license in this repository or chat. Linux PC support ships with the editor;
Unity Web, Windows and Android require their matching build-support modules.
iOS builds require a supported Mac toolchain.

The retained cloud editor now includes Windows Mono support. Its official archive
was checked against Unity's release metadata, exact byte count and integrity hash
before extraction. To reproduce the module installation on this rootless Linux
machine, run `python3 Tools/CloudSetup/install-windows-support.py`. The installer
preserves TLS/checksum verification and does not execute macOS installer scripts.
`ProductionBuild.Windows` explicitly uses the available Mono backend. Module
installation alone does not activate Unity or prove a Windows build works.

```sh
export UNITY_EDITOR_PATH=/path/to/6000.6.3f1/Editor/Unity
bash Tools/CloudSetup/verify-unity.sh
bash Tools/CloudSetup/verify-unity.sh --build
```

The first command sets up imported art/data and runs real EditMode and PlayMode
tests. The second additionally builds Linux PC and Unity Web. Each invocation saves
fresh logs/XML in its own ignored `Logs/Verification/run.*` directory. Graphics captures require a graphics-capable Unity
run; a headless rules pass is not a rendering check. Other targets are available
through the Wreckabulary/Build menu or `ProductionBuild.Windows`/`.Android`.

On a Windows laptop, install **6000.6.3f1** in Unity Hub, sign in and activate
**Unity Personal** through Hub's license settings on that laptop. For builds,
the Windows editor supplies PC/Mono support; add matching Web Build Support in
Hub. Pull/check Git LFS as above, open the project once to finish import, then
close the editor before the batch run. No activation bypass or credential/license
transfer is needed; never
paste credentials or license contents into chat or this checkout.

From the repository root in Windows PowerShell 5.1 or PowerShell 7:

```powershell
.\Tools\CloudSetup\verify-unity.ps1
.\Tools\CloudSetup\verify-unity.ps1 -Build
# For a nondefault Hub install location:
.\Tools\CloudSetup\verify-unity.ps1 -UnityEditorPath 'D:\Unity\6000.6.3f1\Editor\Unity.exe' -Build
```

Check `$LASTEXITCODE` after either command; only `0` is success.
The default is `%ProgramFiles%\Unity\Hub\Editor\6000.6.3f1\Editor\Unity.exe`;
`UNITY_EDITOR_PATH` also selects the editor. `-ResultsRoot` or
`WRECK_VERIFY_RESULTS` selects another log parent. The helper checks the project
pin and executable version, calls only `ProjectSetup.Run` for setup (never
`PrototypeBuilder`), and saves fresh logs/XML in a unique `run.*` directory.
Both suites must report actual nonzero passing test cases; missing/malformed,
zero-test, all-skipped or failing reports stop the run. Native Unity failures
retain their exit code. `-Build` runs `ProductionBuild.Windows` and `.Web` only
after both suites pass, checks each fresh successful build log and output, and
writes `Builds/Windows/Wreckabulary.exe` and `Builds/UnityWeb/`. Existing production
build outputs can be replaced; scene edits are not regenerated by this helper.
If Windows blocks the script, follow your machine's approved script-signing or
execution-policy process; the helper does not change system policy. Headless
verification does not establish rendering quality or device performance.

The standalone HTML edition lives in `Web`; its README gives build, tests and
server instructions. Its output is separate from a Unity Web build. Dependencies
are bundled locally; no runtime CDN or image/model provider keys are needed.
